Profile Blueprint

디자인 전공 지식과 프론트엔드 구현 능력을 융합한 핵심 프로필 도면입니다.

SYSTEM_SPECIFICATION

대전과학기술대학교 컴퓨터공학&그래픽과에서 컴퓨터공학과 그래픽을 함께 배우며, 화면 설계와 프론트엔드 구현에 관심을 갖게 된 박주은입니다.

그래픽과 UI 디자인 경험을 통해 화면의 구조, 정보의 우선순위, 사용자 흐름을 고민해왔고, 이를 React, TypeScript, HTML, CSS, JavaScript 기반의 실제 웹 화면으로 구현하는 데 집중하고 있습니다.

제가 프론트엔드를 선택한 이유는 사용자가 제품을 이해하고 신뢰하는 첫 경험이 화면에서 시작된다고 생각하기 때문입니다. 입력, 확인, 오류 대응, 저장, 이동 흐름처럼 사용자가 직접 마주하는 과정을 설계하고 구현하는 점에 매력을 느꼈습니다.

저의 강점은 디자인 감각과 구현 사고를 함께 가져갈 수 있다는 점입니다. 아직 백엔드와 대규모 시스템 설계 경험은 깊지 않지만, API 연동, 데이터 저장 흐름, fallback, 사용자 확인 단계처럼 프론트엔드가 제품 흐름과 만나는 지점을 중심으로 역량을 쌓고 있습니다.

PetLog, VetFlow, Chartive 프로젝트를 통해 AI 분석 초안, 사용자 확인, 데이터 저장, 대시보드 UI, Vanilla JavaScript 인터랙션을 직접 구현하며 화면과 데이터 흐름을 연결하는 경험을 쌓고 있습니다.

01 / DESIGN

Design Background

컴퓨터공학&그래픽 전공과 UI 디자인 경험을 통해 화면 구조, 시각적 위계, 정보 전달 방식을 함께 고민합니다.

02 / FRONTEND

Frontend Implementation

React, TypeScript, HTML, CSS, JavaScript를 활용해 입력 폼, 상태 카드, 반응형 레이아웃, 인터랙션 UI를 구현합니다.

03 / PRODUCT FLOW

Product Flow

AI API, Firebase, fallback, 사용자 확인 단계를 연결해 단순 화면이 아니라 실제 사용 흐름으로 이어지는 프론트엔드 구조를 구성합니다.

ACTION

RESULT

Engineering Decisions

  • AI 결과를 바로 저장하지 않고 사용자 검토 단계 추가

    OCR 분석의 신뢰성 한계를 인정하고 오분류 데이터가 DB에 직접 적재되는 문제를 방지했습니다.

  • OCR 실패 상황에 대비한 수기 입력 fallback 제공

    API 응답 지연이나 영수증 훼손 등으로 분석이 불가능한 상황에서도 원활히 기록할 수 있게 흐름을 보완했습니다.

  • Firebase 접근 로직과 화면 로직 분리

    Service Layer 패턴 클래스로 Firebase 데이터 호출을 캡슐화하여 화면 컴포넌트의 비즈니스 로직 책임을 낮추었습니다.

  • TypeScript 타입 기반 분석 데이터 구조 관리

    OCR 응답 객체와 데이터베이스 모델에 엄격한 타입을 적용하여 개발 중 버그 유발을 방지했습니다.
