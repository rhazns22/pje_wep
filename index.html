01
> BACKGROUND & VISION

컴퓨터공학과 그래픽을 함께 배우며, 화면을 보기 좋게 만드는 것뿐 아니라 사용자가 실제로 이해하고 사용할 수 있는 흐름을 설계하는 데 관심을 갖게 되었습니다.

02
> DEVELOPMENT PHILOSOPHY

저는 프론트엔드를 단순히 UI를 구현하는 영역이 아니라, 사용자의 입력, 확인, 오류 대응, 데이터 저장, 결과 확인까지 이어지는 실제 서비스 흐름을 만드는 역할이라고 생각합니다.

03
> EXPERIENCE: PETLOG

PetLog에서는 AI 영수증 분석 결과를 바로 저장하지 않고, 사용자가 직접 확인한 뒤 Firebase에 저장하는 구조를 구현했습니다. 이를 통해 AI 결과의 한계를 고려한 사용자 검토 흐름, fallback UI, 데이터 저장 구조를 경험했습니다.

04
> EXPERIENCE: CHAENGIM

챙김 프로젝트에서는 복잡하게 흩어져 있는 정부 혜택 정보를 카드, 태그, 신청 상태 UI, 체크리스트 구조로 정리하며 사용자가 필요한 혜택과 준비 과정을 빠르게 이해할 수 있는 정보 구조와 화면 흐름을 설계했습니다.

05
> STRENGTHS & GROWTH

저의 강점은 디자인 감각과 구현 사고를 함께 가져갈 수 있다는 점입니다. 화면의 시각적 위계, 정보 구조, 사용자 흐름을 고민하면서 React, TypeScript, JavaScript, Firebase 기반의 실제 서비스 흐름으로 연결하는 프론트엔드 엔지니어로 성장하고 있습니다.

PROBLEM

AI OCR 결과를 바로 저장하면 오분류 위험이 있고, 동물병원 영수증의 항목과 금액 구조가 복잡해 사용자가 검토할 수 있는 단계가 필요했습니다.

ACTION

AI 분석 결과는 초안으로만 사용하고, 사용자가 항목을 확인·수정한 뒤 최종 데이터가 Firebase에 저장되도록 검토 흐름을 구성했습니다.

RESULT

영수증 업로드 → AI 분석 → 사용자 확인 → 기록 저장으로 이어지는 실제 사용 가능한 데이터 입력 흐름을 구현했습니다.

Engineering Decisions

AI 결과를 바로 저장하지 않고 사용자 검토 단계를 추가

OCR 실패 상황에 대비한 수기 입력 fallback 제공

API 응답 지연, 영수증 손상, 분석 실패 상황에서도 사용자가 기록을 이어갈 수 있도록 수기 입력 흐름을 보완했습니다.

Firebase 접근 로직과 화면 로직 분리

Firebase 데이터 호출을 서비스 계층으로 분리해 화면 컴포넌트가 비즈니스 로직에 과하게 의존하지 않도록 구성했습니다.
